# Plan: Abyss Loader — Eyes, Walking Wizard, Descent Text

## Goal

Replace the current preloader with a themed one: two SVG eyes shut at 0% that open as loading progresses, a wizard that walks along the progress bar to 100%, and abyss-themed status text. The eyes are the visual centerpiece.

## Context

The site already has a **working, real** loader. It is not a fake timer, and its logic must be carried over rather than rewritten:

- `index.html:63-77` — markup: `.loader__mark`, `.loader__ring` (SVG circle), `.loader__name`, `.loader__track > #loaderBar`, `.loader__pct > #loaderPct`, `.loader__status > #loaderStatus`, `.loader__scan`.
- `css/style.css:171-267` — the loader styles block.
- `js/main.js:719-796` — the loader IIFE. Critical behaviors to preserve:
  - `shown`/`target` easing in `paint()` (rAF loop, 0.12 lerp, snaps when within 0.4).
  - `setTarget(v, label)` — monotonic target, clamped 0-100, sets status text.
  - Real asset tracking: three portrait images (`alish-900.jpg`, `alish-900.webp`, `alish-1100.webp`) via `Image()` with `onload`/`onerror` → `settle()`.
  - Staged crawl to 90% until `window.load`, then 100.
  - **`finish()`** — adds `.is-done` + `html.is-loaded`, then `hidden` after 700ms.
  - **Failsafe `setTimeout(finish, 6000)`** — guarantees the page opens even if an asset never fires. Must not be weakened.
  - `reduced` motion short-circuit: adds `.is-done` immediately and returns.

`css/cinematic-loader.css` is untracked, unreferenced by any HTML, and targets a `.cinematic-loader` that does not exist. It is a separate abandoned attempt. **Leave it alone** (out of scope).

## Decisions (confirmed with user)

## Tasks

### 1. `index.html` — replace loader markup (lines 63-77)

Keep the same IDs the JS depends on (`#loaderBar`, `#loaderPct`, `#loaderStatus`) and the same `role="status" aria-live="polite"` on the root. Replace `.loader__mark`/`.loader__ring` with an eye pair, and add the wizard.

```html
<div class="loader" id="loader" role="status" aria-live="polite">
  <div class="loader__inner">
    <p class="loader__name">ALISH<em>SHRESTHA</em></p>

    <!-- Two eyes. The lid paths are driven by --open (0..1), set from JS. -->
    <div class="loader__eyes" aria-hidden="true">
      <svg class="eye" viewBox="0 0 120 72" data-eye="left">
        <defs>
          <clipPath id="eyeLid"><path class="eye__lid" d=""/></clipPath>
        </defs>
        <g clip-path="url(#eyeLid)">
          <ellipse class="eye__ball" cx="60" cy="36" rx="34" ry="26"/>
          <circle class="eye__iris" cx="60" cy="36" r="13"/>
          <circle class="eye__pupil" cx="60" cy="36" r="5.5"/>
          <circle class="eye__glint" cx="52" cy="27" r="2.6"/>
        </g>
        <path class="eye__lash" d="M6 36 A54 34 0 0 1 114 36"/>
      </svg>
      <svg class="eye" viewBox="0 0 120 72" data-eye="right"> <!-- mirrored --> </svg>
    </div>

    <div class="loader__track" aria-hidden="true">
      <i id="loaderBar"></i>
      <svg class="wizard" viewBox="0 0 24 32"> <!-- hat, robe, two legs --> </svg>
    </div>

    <p class="loader__pct"><span id="loaderPct">0</span>%</p>
    <p class="loader__status" id="loaderStatus">Descending</p>
  </div>
  <div class="loader__scan" aria-hidden="true"></div>
</div>
```

Notes:
- Two separate `<clipPath>` ids (`eyeLid`, `eyeLidR`) — duplicate ids are invalid and the second clipPath would be ignored.
- The wizard SVG sits **inside** `.loader__track` so it can be positioned with `left: var(--pct)`. The track is `overflow: hidden` today; the wizard must be allowed to overhang slightly or sit just above the bar, so give the track `overflow: visible` and clip nothing (the bar fill is a child `i`, already sized by width).
- Wizard leg animation: two `<path>` legs, rotated around a hip point via `transform-box: fill-box; transform-origin: top`.

### 2. `css/style.css` — replace the loader block (lines 171-267)

Delete `.loader__mark`, `.loader__glyph`, `.loader__ring`, `glyphPulse`, `barPulse`, and the `@media (max-width:480px) { .loader__track }` rule. Keep `.loader`, `.loader__inner`, `.loader__name`, `.loader__track`, `.loader__track i`, `.loader__pct`, `.loader__status`, `.loader__scan` (extend as noted below) and the `@media (prefers-reduced-motion: reduce) { .loader { display: none } }` rule.

New rules:

- **Eye aperture.** The lid path is generated geometry, so drive it from a single custom property. Register it so it interpolates:
  ```css
  @property --open { syntax: '<number>'; inherits: true; initial-value: 0; }
  ```
  Build the lid as a shape whose height is proportional to `--open`, using a `clipPath` whose path `d` is set by JS (the one thing CSS cannot express). Alternative if path morphing proves fiddly: clip with `transform: scaleY(var(--open))` on a wrapper and `transform-origin: center` — simpler, no JS geometry, and visually near-identical. **Prefer the scaleY approach**; fall back to path generation only if the eyes read as fake.
- `.eye` sized `clamp(7rem, 22vw, 12rem)` wide, laid out in a flex row with a gap; `transform: scaleY(var(--open))` on `.eye__lid-clip` / the eye group, `transition: transform .5s var(--ease)`.
- Iris tracks slightly: `.eye__iris, .eye__pupil { transform: translateX(calc(var(--open) * 4px)); }` — a small drift as the eye opens, not a full look-around.
- Eyes glow faintly as they open: `filter: drop-shadow(0 0 calc(var(--open) * 14px) rgba(167,139,250,calc(var(--open) * .5)))`.
- **Wizard.** `position: absolute; bottom: 100%; left: var(--pct);` on the track, so it rides the fill head. `transform: translateX(-50%)`. Walking cycle via a `steps()`-ish keyframe alternating the two legs, gated on a `.is-walking` class so it stops when loading finishes.
- `.loader__track` → `position: relative; overflow: visible;`
- `.loader__scan` → keep, but retune so it does not cross the eyes at full strength; lower opacity to `.35`.
- Under `prefers-reduced-motion: reduce`, in addition to `.loader { display: none }`, ensure the eye/wizard animations are also disabled (belt and braces, since the display:none rule should already cover it).

## Risks

- **Failsafe regression is the real danger.** The loader must never trap a user. Any refactor of `finish()`, the `window.load` handler, or the 6000ms timeout can leave the page permanently black. Keep those lines byte-identical unless the change is provably behavior-preserving.
- **Eye aperture via `scaleY`** squashes the iris and highlight along with the lid if applied to the whole eye group. It must be applied to a clip wrapper only, so the eyeball and iris stay undistorted.
- **Wizard inside `.loader__track`** — the track is a 2px-tall element. Positioning the wizard with `bottom: 100%` puts it above the bar; if the track keeps `overflow: hidden` the wizard is invisible. This is the single most likely thing to get wrong; check it first when testing.
- **`--open` with `@property`** — if unsupported, the eyes stay shut at 0% forever. The scaleY fallback (transform-based) does not need `@property`; prefer it.
- Reduced motion: the existing rule sets `.loader { display: none }`, so the loader never shows. Confirm the eyes are not left stuck half-open in the DOM behind it (harmless visually, but tidy it by setting `--open: 1` in the reduced-motion branch).
